まとめ: 最初に直すこと

  1. Ollama を更新する（リスク）。0.32.4 は CVE-2026-85180 の報告対象範囲に入っています。
  2. 4 GB に収まるモデルを使う（速度）。それより大きいモデルは一部が CPU で動きます。
  3. API は localhost のままにする（すでに良好）。認証を加えずに OLLAMA_HOST を変えないでください。

1. セキュリティ

リスク: Ollama 0.32.4 には既知の脆弱性がある

CVE-2026-85180 は Ollama 0.30.0 から 0.33.2 について報告されています。悪意あるモデルレジストリが、モデルの pull を内部ネットワークのアドレスへリダイレクトできます（SSRF）。お使いの Ollama は 127.0.0.1 でしか待ち受けていないため、攻撃者はあなたに自分が管理するレジストリからモデルを pull させる必要があり、実際のリスクは低いと言えます。修正されたバージョンについては情報源によって食い違いがあるため、最低バージョンを選ぶのではなく最新リリースに更新してください。そうすれば、途中のバージョンで当たってしまう CVE-2026-103663（0.34.2 から 0.35.0 まで）も避けられます。

# Windows: download and run the current installer
https://ollama.com/download
# then confirm
ollama --version

（コメントの意味: Windows では最新のインストーラーをダウンロードして実行し、その後バージョンを確認する。）モデルは ollama.com/library か、信頼できる公開元からだけ pull してください。

OK: ネットワークには何も公開されていない

Ollama は 127.0.0.1:11434 でのみ応答し、ほかのローカル AI のポートも開いていません。あとで別のデバイスから使いたくなっても、OLLAMA_HOST=0.0.0.0 だけを設定するのはやめてください。認証付きのリバースプロキシを前に置き、Windows Defender ファイアウォールで自分のデバイスからだけポートを許可します。手順: HARDENING.md（英語）。

2. 速度

GTX 1050 の VRAM は 4 GB です。デスクトップとドライバーが使う分を除くと、モデルとそのコンテキストに使えるのは約 3.5 GB です。収まらない分は CPU で動き、たいてい数倍遅くなります。

モデルの大きさQ4_K_M、コンテキスト 4k の場合この GPU では
1-2B約 1.5-2.2 GBすべて収まり、速い
3-4B約 2.8-3.4 GB収まるが、コンテキスト 4k ではぎりぎり
7-8B約 5-6 GB約 60% が GPU、目に見えて遅い
14B 以上9 GB 以上ほとんど CPU、遅い

このカードでコーディングの補助や要約をするなら、普段は Q4_K_M の 3-4B モデル（たとえば qwen3:4b、2.5 GB）を使い、速度より品質が大事なときは 7-8B モデルを使ってください。GPU のサイズごとの最新のおすすめはお使いの GPU に収まるモデル（英語）にあります。分担は次のコマンドで確認できます:

ollama ps
# PROCESSOR should read "100% GPU"; a CPU/GPU split means it didn't fit

（コメントの意味: PROCESSOR 列が "100% GPU" になっているべきで、CPU/GPU に分かれていれば収まっていない。）3-4B モデルでも分かれている場合は、コンテキスト長を下げてください。対話セッションでは /set parameter num_ctx 2048 で設定できます。ゲームや動画タブを多く開いたブラウザーなど、GPU を多く使うアプリは閉じてください。

3. 整理

  • 使わなくなったモデルを削除して（ollama rm <name>、name はモデル名）ディスクを空けてください。モデルが 8 個あれば 30 GB 以上になることもよくあります。
  • 更新後に python local_ai_checkup.py を再実行してください。リスクは 0 件になるはずです。
