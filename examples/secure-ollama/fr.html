Mon Ollama est-il exposé ? Une liste de contrôle pour le verrouiller

Par MV2 de Munim, Inc. Réglages vérifiés d'après la FAQ d'Ollama le 12 octobre 2026. Uniquement pour vos propres machines. Cette page a été traduite avec une IA à partir de l'original en anglais ; en cas d'écart, l'original fait foi.

Pourquoi c'est important : l'API d'Ollama n'a pas d'authentification. Toute personne qui atteint le port 11434 peut lister, télécharger, créer et supprimer des modèles, utiliser votre GPU et accéder à tous les points de terminaison concernés par les CVE de cette année (voir CVE d'Ollama, en anglais). Par défaut, Ollama écoute sur 127.0.0.1:11434, ce qui est sûr. Il se retrouve généralement exposé plus tard : quand on définit OLLAMA_HOST=0.0.0.0 (ou qu'on active dans l'application le réglage « Expose Ollama to the network ») pour qu'une autre machine ou un conteneur Docker puisse s'y connecter, ou quand Docker publie le port.

1. Vérifier sur quelle adresse il écoute

  • Linux : ss -tlnp | grep 11434
  • macOS : lsof -nP -iTCP:11434 -sTCP:LISTEN
  • Windows : netstat -ano | findstr :11434
  • Docker : docker ps --format "{{.Names}} {{.Ports}}"

127.0.0.1:11434 signifie que seule cette machine peut se connecter : cette étape est terminée. 0.0.0.0:11434, *:11434, [::]:11434 ou un port Docker comme 0.0.0.0:11434->11434/tcp signifie que d'autres machines peuvent aussi se connecter. Pour le confirmer, lancez curl http://<this machine's LAN IP>:11434/api/version depuis un autre appareil qui vous appartient (avec l'adresse IP locale de cette machine). Si la réponse contient un numéro de version, le port est ouvert sur votre réseau.

Le script gratuit local-ai-checkup effectue ces vérifications pour vous, ainsi que celles de version, d'OLLAMA_ORIGINS et des ports Docker ci-dessous. Il ne fait que lire et n'envoie rien hors de la machine.

2. Si seule cette machine a besoin d'Ollama : le lier à localhost

Supprimez OLLAMA_HOST ou réglez-le sur 127.0.0.1:11434, et désactivez « Expose Ollama to the network » dans les réglages de l'application s'il est activé :

  • Linux (systemd) : lancez sudo systemctl edit ollama.service et supprimez toute ligne Environment="OLLAMA_HOST=0.0.0.0...", ou, sous [Service], indiquez : 
    [Service]
Environment="OLLAMA_HOST=127.0.0.1:11434"
    puis lancez sudo systemctl daemon-reload && sudo systemctl restart ollama.
  • macOS (application) : launchctl setenv OLLAMA_HOST "127.0.0.1:11434" (ou launchctl unsetenv OLLAMA_HOST), puis quittez Ollama et rouvrez-le.
  • Windows : quittez Ollama depuis la barre des tâches. Ouvrez « Modifier les variables d'environnement pour votre compte », supprimez ou modifiez OLLAMA_HOST, puis relancez Ollama depuis le menu Démarrer.

Si vous avez défini OLLAMA_HOST=0.0.0.0 uniquement pour qu'un conteneur Docker puisse se connecter, il existe des solutions qui gardent Ollama hors de votre réseau : voir Docker can't reach Ollama (en anglais). Si vous l'avez défini pour vous connecter depuis un portable ou un téléphone, voir Utiliser Ollama depuis un autre ordinateur ou un téléphone (en anglais).

3. Si vous faites tourner Ollama dans Docker

-p 11434:11434 publie le port sur toutes les interfaces. Sous Linux, Docker écrit ses propres règles de pare-feu, donc ufw et firewalld ne le bloquent pas. Utilisez plutôt l'une de ces options :

docker run -d --gpus=all -v ollama:/root/.ollama -p 127.0.0.1:11434:11434 --name ollama ollama/ollama

Si Open WebUI (ou n8n, Dify, Flowise) tourne dans le même fichier Compose, Ollama n'a besoin d'aucun port publié. L'autre conteneur le joint par le nom du service :

services:
  ollama:
    image: ollama/ollama
    volumes: [ "ollama:/root/.ollama" ]
    # no "ports:" here - only containers on this network can reach it
  open-webui:
    image: ghcr.io/open-webui/open-webui:main
    environment:
      - OLLAMA_BASE_URL=http://ollama:11434
    ports: [ "127.0.0.1:3000:8080" ]
    volumes: [ "open-webui:/app/backend/data" ]
volumes:
  ollama: {}
  open-webui: {}

(Le commentaire du fichier signifie : pas de « ports: » ici, seuls les conteneurs de ce réseau peuvent le joindre.) Recréez les conteneurs après modification (docker compose up -d) et refaites l'étape 1.

4. Si d'autres machines en ont vraiment besoin : placer une authentification devant

Liez Ollama à 127.0.0.1 comme à l'étape 2, puis faites d'un proxy inverse avec authentification la seule porte d'entrée. Un exemple minimal avec Caddy (créez le hachage avec caddy hash-password) :

ollama.home.example {
    basic_auth {
        alice <hash from caddy hash-password>
    }
    reverse_proxy 127.0.0.1:11434 {
        header_up Host localhost:11434
    }
}

La ligne Host compte. Les exemples de proxy de la FAQ d'Ollama réécrivent l'en-tête Host en localhost:11434, et les requêtes avec d'autres valeurs de Host peuvent être refusées. Un réseau privé comme Tailscale ou WireGuard est une autre option : seuls vos propres appareils atteignent le port, et rien n'est publié sur Internet. Use Ollama remotely (en anglais) présente un tunnel SSH, Tailscale (y compris la raison pour laquelle tailscale serve devant Ollama renvoie 403) et une règle de pare-feu limitée au réseau local.

Des applications plutôt que des personnes ? Open WebUI, n8n et les clients compatibles OpenAI envoient une clé d'API sous la forme Authorization: Bearer, que l'authentification basique refuse. Ollama API key (en anglais) fournit des configurations Caddy et nginx qui vérifient une clé, ainsi que les réglages de chacun de ces clients.

Tunnels : la FAQ montre aussi des commandes ngrok et cloudflared. Seules, elles publient votre Ollama sur tout Internet sans authentification. Ne les utilisez qu'avec le contrôle d'accès du fournisseur de tunnel activé.

5. Garder OLLAMA_ORIGINS restreint

OLLAMA_ORIGINS détermine quelles pages web votre navigateur autorise à parler à Ollama. Par défaut, seules les origines locales sont autorisées. Avec *, n'importe quel site que vous visitez peut envoyer des requêtes à votre Ollama local et lire les réponses. N'ajoutez que les origines précises dont vous avez besoin, par exemple l'identifiant d'une seule extension de navigateur au lieu de chrome-extension://*. La vérification dans le navigateur (en anglais), en un clic, indique si un site web peut lire votre Ollama (ou LM Studio) en ce moment.

6. Si Open WebUI tourne devant

  • Créez d'abord votre compte administrateur, puis définissez ENABLE_SIGNUP=False (ou désactivez les inscriptions dans les réglages d'administration) pour que les inconnus qui trouvent la page ne puissent pas s'inscrire.
  • Gardez la valeur par défaut DEFAULT_USER_ROLE=pending pour que les nouveaux comptes doivent être approuvés, et définissez un WEBUI_SECRET_KEY fixe pour que les sessions survivent aux redémarrages.
  • Passez à la dernière version. Les versions antérieures à 0.11.4 sont concernées par plus de 15 avis de sécurité de septembre 2026 que la plupart des scanners ne connaissent pas. Voir Open WebUI (en anglais).

7. Rester à jour

Vérifiez vos versions avec le vérificateur de CVE gratuit (en anglais), qui couvre aussi vLLM, n8n, Dify, RAGFlow, AnythingLLM, Langflow, Flowise et LiteLLM, y compris des avis sans identifiant CVE. Le flux Atom liste chaque mise à jour de ce site.
