Is my Ollama exposed? A checklist to lock it down

By MV2 of Munim, Inc. Settings checked against the Ollama FAQ on 12 October 2026. For your own machines only.

Why it matters: Ollama's API has no login. Anyone who can reach port 11434 can list, pull, create and delete models, use your GPU, and reach every endpoint that this year's CVEs live in (see Ollama CVEs). Ollama binds to 127.0.0.1:11434 by default, which is safe. It usually gets exposed later, when OLLAMA_HOST=0.0.0.0 is set (or the app's "Expose Ollama to the network" setting is turned on) so another machine or a Docker container can connect, or when Docker publishes the port.

1. Check what it is listening on

  • Linux: ss -tlnp | grep 11434
  • macOS: lsof -nP -iTCP:11434 -sTCP:LISTEN
  • Windows: netstat -ano | findstr :11434
  • Docker: docker ps --format "{{.Names}} {{.Ports}}"

127.0.0.1:11434 means only this machine can connect, and you're done with this step. 0.0.0.0:11434, *:11434, [::]:11434 or a Docker port like 0.0.0.0:11434->11434/tcp means other machines can connect too. To confirm, run curl http://<this machine's LAN IP>:11434/api/version from another device you own. A version number in the reply means the port is open to your network.

2. If only this machine needs Ollama: bind it to localhost

Remove OLLAMA_HOST, or set it to 127.0.0.1:11434, and turn off "Expose Ollama to the network" in the app's Settings if it's on:

  • Linux (systemd): run sudo systemctl edit ollama.service and delete any Environment="OLLAMA_HOST=0.0.0.0..." line, or under [Service] set: 
    [Service]
Environment="OLLAMA_HOST=127.0.0.1:11434"
    then run sudo systemctl daemon-reload && sudo systemctl restart ollama.
  • macOS (app): launchctl setenv OLLAMA_HOST "127.0.0.1:11434" (or launchctl unsetenv OLLAMA_HOST), then quit and reopen Ollama.
  • Windows: quit Ollama from the taskbar. Open "Edit environment variables for your account", delete or change OLLAMA_HOST, then start Ollama again from the Start menu.

If you set OLLAMA_HOST=0.0.0.0 only so a Docker container could connect, there are ways that keep Ollama off your network: see Docker can't reach Ollama. If you set it so a laptop or phone could connect, see Use Ollama from another computer or your phone.

3. If you run Ollama in Docker

-p 11434:11434 publishes the port on every interface. On Linux, Docker writes its own firewall rules, so ufw and firewalld don't block it. Use one of these instead:

docker run -d --gpus=all -v ollama:/root/.ollama -p 127.0.0.1:11434:11434 --name ollama ollama/ollama

If Open WebUI (or n8n, Dify, Flowise) runs in the same Compose file, Ollama doesn't need a published port at all. The other container reaches it by service name:

services:
  ollama:
    image: ollama/ollama
    volumes: [ "ollama:/root/.ollama" ]
    # no "ports:" here - only containers on this network can reach it
  open-webui:
    image: ghcr.io/open-webui/open-webui:main
    environment:
      - OLLAMA_BASE_URL=http://ollama:11434
    ports: [ "127.0.0.1:3000:8080" ]
    volumes: [ "open-webui:/app/backend/data" ]
volumes:
  ollama: {}
  open-webui: {}

Recreate the containers after editing (docker compose up -d) and repeat step 1.

4. If other machines really need it: put a login in front

Bind Ollama to 127.0.0.1 as in step 2, then let a reverse proxy with authentication be the only way in. A minimal Caddy example (create the hash with caddy hash-password):

ollama.home.example {
    basic_auth {
        alice <hash from caddy hash-password>
    }
    reverse_proxy 127.0.0.1:11434 {
        header_up Host localhost:11434
    }
}

The Host line matters. The Ollama FAQ's proxy examples rewrite the Host header to localhost:11434, and requests with other Host values can be refused. A private network such as Tailscale or WireGuard is another option: only your own devices can reach the port, and nothing is published to the internet. Use Ollama remotely walks through an SSH tunnel, Tailscale (including why tailscale serve in front of Ollama returns 403) and a LAN-only firewall rule.

Apps rather than people? Open WebUI, n8n and OpenAI-style clients send an API key as Authorization: Bearer, which basic auth rejects. Ollama API key has Caddy and nginx configs that check a key, and the settings for each of those clients.

Tunnels: the FAQ also shows ngrok and cloudflared commands. On their own they publish your Ollama to the whole internet with no login. Only use them with the tunnel provider's access control turned on.

5. Leave OLLAMA_ORIGINS narrow

OLLAMA_ORIGINS decides which web pages your browser lets talk to Ollama. By default only local origins are allowed. Setting it to * lets any website you visit send requests to your local Ollama and read the replies. Add only the specific origins you need, such as one browser extension's ID instead of chrome-extension://*. The one-click browser check shows whether a website can read your Ollama (or LM Studio) right now.

6. If you run Open WebUI in front of it

  • Create your admin account first, then set ENABLE_SIGNUP=False (or turn off sign-ups under Admin Settings) so strangers who find the page can't register.
  • Keep the default DEFAULT_USER_ROLE=pending so new accounts need approval, and set a fixed WEBUI_SECRET_KEY so sessions survive restarts.
  • Update to the newest release. Versions before 0.11.4 have 15+ September 2026 advisories that most scanners don't know about. See Open WebUI.
