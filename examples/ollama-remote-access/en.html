Use Ollama from another computer or your phone, without exposing it

By MV2 of Munim, Inc. Checked on 12 October 2026 against the Ollama FAQ, Ollama's server source (server/routes.go), the Tailscale Serve docs, Open WebUI's HTTPS using Tailscale page and LM Studio's server docs. For your own machines only.

The usual advice is "set OLLAMA_HOST=0.0.0.0" (or turn on Settings → Expose Ollama to the network in the macOS and Windows app). That works, but Ollama's API has no login, so it also lets every device on that network use your models, pull and delete them, and reach the endpoints this year's Ollama CVEs are in. If the port is ever forwarded on your router, that means the whole internet. Pick the narrowest option that does the job:

You wantUseWho else can reach Ollama
One laptop you control, now and thenA. SSH tunnelNobody. Nothing new is opened.
Chat from your phone, at home or awayB. Open WebUI over Tailscale ServeOnly your tailnet, and only through Open WebUI's login. Ollama stays on localhost.
Apps on other devices that talk to the Ollama API (another PC's tools, n8n, a phone app)C. Ollama on your tailnetDevices in your tailnet
Other machines on the same home networkD. LAN plus a firewall ruleEvery device on that network, with no login

Don't: forward port 11434 on your router; use tailscale funnel, ngrok or cloudflared on Ollama without the provider's access control (all three publish it to the internet); or set OLLAMA_ORIGINS=* to "make it work". That last one changes which websites can call it, not which devices (see the browser check).

A. SSH tunnel: one laptop, nothing to open

Leave Ollama on its default 127.0.0.1:11434 on the GPU machine. From the laptop:

ssh -N -L 11434:127.0.0.1:11434 you@gpu-box

While that runs, http://127.0.0.1:11434 on the laptop is the GPU machine's Ollama, so ollama list, Open WebUI and anything that defaults to localhost just work. Test it with curl http://127.0.0.1:11434/api/version. If the laptop runs its own Ollama on 11434, forward another port instead (-L 11435:127.0.0.1:11434) and point clients at it, for example OLLAMA_HOST=127.0.0.1:11435 ollama list.

The GPU machine needs an SSH server: usually already on Linux; on macOS, turn on System Settings → General → Sharing → Remote Login; on Windows, add the optional "OpenSSH Server" feature. The ssh client is built into Windows 10/11, macOS and Linux. This also passes Ollama's Host check (below), because the request is addressed to 127.0.0.1.

B. From your phone: Open WebUI over Tailscale Serve

For chatting from a phone, put the phone on a private network with the server and reach Open WebUI, not Ollama. Ollama never leaves localhost, and Open WebUI's accounts stay the gate.

  1. Install Tailscale on the server and on the phone and sign in to the same account on both.
  2. Keep Open WebUI on localhost. In Docker: -p 127.0.0.1:3000:8080 (in Compose: ports: [ "127.0.0.1:3000:8080" ]), with Ollama reached at OLLAMA_BASE_URL as before.
  3. On the server: 
    tailscale serve --bg 3000
tailscale serve status
    The status shows your address, https://<machine>.<tailnet>.ts.net. Tailscale Serve needs HTTPS certificates turned on for your tailnet; the first run sends you to a consent page if they're off. --bg keeps it running after reboots.
  4. Tell Open WebUI its address, as its Tailscale page says: WEBUI_URL=https://<machine>.<tailnet>.ts.net and CORS_ALLOW_ORIGIN=https://<machine>.<tailnet>.ts.net. Recreate the container. (Why these matter, and the cookie and secret-key settings: Open WebUI behind a proxy.)
  5. On the phone, open that address and sign in. "Add to Home Screen" makes it an app icon. Open WebUI's docs note that HTTPS is needed for browser features such as voice calls, which Serve gives you.

Test it: turn the phone's Wi-Fi off and reload: it should still work over mobile data. A device that isn't in your tailnet shouldn't load the address at all. If sign-ups are open in Open WebUI, close them (ENABLE_SIGNUP=False) after creating your accounts. To undo: tailscale serve reset.

Not tailscale funnel. Funnel makes the same address public on the internet. Open WebUI's docs warn about this, and with Open WebUI's September advisories in mind, a private tailnet is the safer default.

C. The Ollama API itself on your tailnet

Some clients need the raw API: Ollama on another PC, n8n or a script on another server, phone apps that connect straight to an Ollama URL.

Why tailscale serve 11434 returns 403

The obvious move, tailscale serve in front of a localhost-only Ollama, gets 403 Forbidden on every request. It isn't Tailscale. When Ollama listens on a loopback address, its allowedHostsMiddleware checks the request's Host header. It accepts only localhost, the machine's own hostname, names ending in .localhost, .local or .internal, and loopback, private or local-interface IPs. That check protects against DNS rebinding from websites. Serve passes <machine>.<tailnet>.ts.net through, which isn't on the list. You can see it on the server itself: curl http://127.0.0.1:11434/api/version answers, while curl -H "Host: gpu-box.example.ts.net" http://127.0.0.1:11434/api/version gets 403. When Ollama listens on a non-loopback address, it skips this check.

Fix 1 (any OS): bind Ollama to the Tailscale address only

  1. Get the server's tailnet IPv4 address: tailscale ip -4 (for example 100.101.102.103).
  2. Set OLLAMA_HOST=100.101.102.103:11434 the way the Ollama FAQ describes. Linux: sudo systemctl edit ollama.service, then add Environment="OLLAMA_HOST=100.101.102.103:11434" under [Service], then sudo systemctl daemon-reload && sudo systemctl restart ollama. macOS app: launchctl setenv OLLAMA_HOST "100.101.102.103:11434", then quit and reopen Ollama. Windows: quit Ollama, set OLLAMA_HOST under "Edit environment variables for your account", then start it from the Start menu. Leave the app's "Expose Ollama to the network" toggle off.
  3. Check what it really listens on (Linux ss -tlnp | grep 11434, macOS lsof -nP -iTCP:11434 -sTCP:LISTEN, Windows netstat -ano | findstr :11434). You want the 100.x address, not 0.0.0.0 or *.
  4. Clients use http://100.101.102.103:11434, or the machine's MagicDNS name, such as http://gpu-box:11434. For the Ollama CLI on another computer: OLLAMA_HOST=http://gpu-box:11434 ollama list.

Two side effects. (1) localhost:11434 stops answering on the server itself. Point local tools at the 100.x address too, for example OLLAMA_HOST=100.101.102.103:11434 ollama run ..., and Open WebUI's OLLAMA_BASE_URL on the same machine. (2) If Ollama starts before Tailscale has its address, binding fails. The Linux unit that Ollama's installer writes has Restart=always and RestartSec=3, so it keeps retrying until it binds. On macOS and Windows, restart Ollama once Tailscale is connected.

Fix 2 (Linux with ufw): listen everywhere, but let only the tailnet in

This keeps localhost:11434 working. Set OLLAMA_HOST=0.0.0.0:11434 (as above), then:

sudo ufw allow OpenSSH            # first, if you manage this box over SSH
sudo ufw default deny incoming
sudo ufw allow in on tailscale0 to any port 11434 proto tcp
sudo ufw enable
sudo ufw status verbose            # no other rule should allow 11434

This covers Ollama installed natively. If Ollama runs in Docker with a published port, ufw doesn't apply: Docker writes its own firewall rules (see Docker can't reach Ollama).

Either way: by default every device in your tailnet can reach every other one. If you've shared the machine with other people, or have devices you trust less, limit port 11434 to your own devices in the tailnet access policy. To also require a key from apps, put a Bearer-key proxy in front.

D. Same home network only: LAN plus a firewall rule

This is fine on a home network you trust. It isn't fine on office, dorm, hotel or café Wi-Fi: everyone on the network, including guests, gets your Ollama with no login.

  1. Set OLLAMA_HOST=0.0.0.0:11434 (steps as in Fix 1, with 0.0.0.0) or turn on the app's "Expose Ollama to the network". Fully quit and reopen Ollama.
  2. Limit who can connect:
    • Linux (ufw): sudo ufw allow from 192.168.1.0/24 to any port 11434 proto tcp (use your own subnet) with default deny incoming, as above.
    • Windows: when Windows asks whether to allow Ollama, allow Private networks only, and make sure your home network's profile is set to Private. Or, in an admin PowerShell: 
      New-NetFirewallRule -DisplayName "Ollama LAN only" -Direction Inbound -Protocol TCP -LocalPort 11434 -RemoteAddress LocalSubnet -Profile Private -Action Allow
      Windows allow rules add up, so also open Windows Defender Firewall → Advanced settings → Inbound Rules and remove or narrow any older Ollama rule that allows Public networks or any address.
    • macOS: the built-in firewall allows or blocks per app, not per subnet. Use option A or C on a Mac instead.
  3. Never add a port forward for 11434 on the router.

Test it: from another device on the network, curl http://<server LAN IP>:11434/api/version should answer. From a phone on mobile data (Wi-Fi off), the same address must not.

LM Studio

LM Studio has its own switches under Developer → Server Settings. From 0.4.0, turn on Require Authentication before Serve on Local Network, create a token under Manage Tokens with only the permissions the client needs, and have clients send Authorization: Bearer <token>. Authentication is off by default. Leave Enable CORS off unless a web page truly needs it (the browser check tests port 1234 too). Options A, C and D work the same way with port 1234, for example ssh -N -L 1234:127.0.0.1:1234 you@gpu-box.
